# 公開版の標準画面での返信と回答

macOS版 Orca 1.4.277 のネイティブ画面を Orca Computer Use で確認した。公開タグ、Community カタログ、導入済みプラグインは `yoshhiide.session-board` v0.2.8、コミット `8ebede1a984dcc2f22d7fa814e287534f55b6008`、配布ハッシュ `954b386b4ba3f9c9b42a6abde7e2fab7989be18059118c6d6dae7027b080c194` で一致した。導入前に稼働していた `local.session-board` v0.2.6 は別のフォルダ版。公開版は既存の Orca 承認フローで導入した。

タグの `dist/` と実機にインストールされた HTML、CSS、パネルとワーカーのバンドルを照合した。ワーカーはアプリ同梱 CLI を `--environment local --json` で使用する。macOS のアクセシビリティ許可は導入前から有効で、Orca ウィンドウを1つ、未切り詰めの AX スナップショットを取得できた。

対象の Bot が展開されている状態で、一覧の「返信」から QA 項目の標準コメント欄に、詳細の「標準画面で回答」から2問目「形」の回答欄にフォーカスした。各欄で架空の下書きを入力し、消去した。別 Bot の Home Chat から通常項目へ切り替える操作も確認した。

別の Bot を開いている状態で対象 Bot を折りたたむと、公開版 v0.2.8 の返信操作はプラグイン詳細の「標準の返信画面を確認できませんでした。」まで進み、別 Bot の標準画面に留まった。AX 上では対象 Bot の名前と `button Unfold <Bot>` が存在し、Home Chat はまだ存在しなかった。CLI による項目照合とウィンドウ取得の後、最初の AX 操作を選ぶ時点で停止していた。

修正版は対象 Bot の開閉ボタンを照合し、展開後に取り直した AX スナップショットから Home Chat を選ぶ。Bot の切り替え後も従来どおり項目と質問を照合する。実際のフォーカスが確認できない通常返信は失敗として扱う。Bot Home を開けないときと macOS のアクセシビリティ許可が必要なときは、パネルに対応する案内を表示する。

配布時にはタグからファイルを展開して `orca plugin validate`、`inspect`、`check` を実行する。HTMLパネルの操作は `check` の対象外なので、Orca 実機で確認する。
