# 標準返信の所要時間と停止箇所

macOS の Orca 1.4.277 で、Community から正式導入した `yoshhiide.session-board` v0.2.11 を Orca Computer Use で操作した。日本語設定、表示中の Orca ウィンドウ1つ、アクセシビリティ許可あり、フォルダ版 v0.2.6 と併存。検証用の予定項目の通常返信は別Botを開き、対象の予定グループを閉じた状態から測った。複数質問は別Botの画面を起点とし、公開パネルで開いた詳細の2問目（自由記述）のボタンを起点とした。

計時はパネルのボタンへの AXPress 呼び出し直前から。Orca Computer Use の応答時間と、次に観測できた AX スナップショットまでの時間を含む。到達しなければ12秒で打ち切った。ワーカーの段階別診断は別の時計で計時する。

v0.2.11 の予定項目への通常返信は、同条件の3回中2回で編集欄まで到達し、フォーカス確認は3.58秒と3.63秒だった。1回はBotの表示後に停止。直後の標準画面では予定グループが開き対象行が見え、ログには `element_not_found` が残った。自由記述では、回答先を切り替えたあとの空欄プレースホルダーが選択肢付き質問の文言から `Reply to <Bot>…` に変わる。v0.2.11 の確認処理はこの表示を受理せず、入力欄へ実際に移動できた場合でも、成功として確定できない。

v0.2.12 は独立した対象照合とウィンドウ・権限確認を並行化し、質問IDを指定した照合では該当するイベントを含むページを直接取得する。AX操作から返る完全なスナップショットで次段階を確認できた場合は再取得を省く。AX要素が失効した場合だけ、対象を再確認して新しい要素番号を選び直す。自由記述とすでに選択済みの質問でも、対象の質問表示、空欄、編集フォーカスを照合する。

受付はパネルのステータスへすぐに表示する。停止段階と対応方法を通知・パネルに出し、ログには段階名、経過時間、成否のコードを出す。ログにはBot名、項目名、質問文、下書きを含めない。複数窓については架空応答で、対象アプリの可視ウィンドウが1つならその窓を照合し、複数表示ならAXPressを行わないことを確認した。複数窓・別Spaceと別マシンは実機未確認。
