# Botのサイドバー表示と標準返信

Orca 1.4.277 のmacOS実機を Orca Computer Use で操作した。Community から更新済みの `yoshhiide.session-board` v0.2.9 を確認し、公開キーでパネルを開いた。フォルダ版 `local.session-board` v0.2.6 も同時に稼働していた。

別Botを開き、対象Botの行が未読かつ折りたたまれている状態で、公開パネルから架空の質問の2問目を選択した。パネルに「Botのホームを開けませんでした。サイドバーにBotを表示して再試行してください。」と表示され、別Botに留まった。最初に停止したのは Bot Home を開く前の照合。AX には `button Unfold <Bot>` が出たものの、その兄弟要素は `text <Bot>` ではなく `container, Text: 未読: <Bot>` だった。対象BotのHome Chatを先に開くと、公開パネルの一覧返信と2問目への回答から、それぞれ対応する標準入力欄にフォーカスした。下書きを入力して消去した。

v0.2.10では既存の `orca://bot/<id>` を利用し、項目の所有者と一致する単一のローカルBotを確認した上で、そのBotのHome Chatへ移動する。移動先のBotと標準項目、質問、フォーカスを従来どおり読み戻す。別BotのHomeに留まった場合は入力欄に触れない。

修正版のワーカーをMac上で動かし、別Botから左サイドバー全体を閉じた状態の通常返信と、Botsグループを閉じた状態の2問目への回答を確認した。どちらも対象Botの行がAXにない状態から対象の入力欄にフォーカスし、架空の下書きを入力・消去できた。画面全体に他の項目やチャットが映るため、証跡はQA項目に絞ったAX観測を記録した。
